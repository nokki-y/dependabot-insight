# AI モデル選定

> [English](./ai-model-selection.md) | 日本語

このドキュメントでは、dependabot-insight の QA レポート生成に使用するデフォルト AI モデルの選定根拠を説明します。

## デフォルトモデル

`claude-sonnet-4-6`（Claude Sonnet 4.6）

## なぜ Sonnet か？

QA レポート生成タスクには以下の特性があります:

| 特性 | 詳細 |
|------|------|
| **入力** | 構造化されたマークダウン（テーブルやリストを含む影響解析サマリー） |
| **出力** | 構造化されたマークダウン（固定テンプレートに従う QA レポート） |
| **必要な推論力** | 中程度 — 影響範囲からテストケースを論理的に導出、依存区分の分類 |
| **必要な創造性** | 低い — テンプレートに従い、具体的な検証コマンドを生成 |
| **レイテンシ要件** | 低い — CI で非同期実行されるため、インタラクティブではない |

### このタスクにおけるモデル比較

| モデル | 適合度 | 理由 |
|--------|--------|------|
| **Claude Opus** | 過剰 | 構造化された入出力とテンプレート追従型のタスクに Opus レベルの推論力は不要。コストとレイテンシが増加する一方、品質向上は限定的。 |
| **Claude Sonnet** | 適切 | 依存区分の分類、テストケースの導出、検証コマンドの生成に十分な推論力を持つ。品質・速度・コストのバランスが最適。 |
| **Claude Haiku** | リスクあり | テストケースが浅くなる、または影響関係の微妙なニュアンスを見落とす可能性がある。影響範囲から具体的なテスト手順への論理的導出には Sonnet の推論力が有効。 |

## デフォルトの変更方法

`ai-model` 入力パラメータで別のモデルを指定できます:

```yaml
- uses: nokki-y/dependabot-insight@v1
  with:
    ai-model: 'claude-opus-4-6'  # より高品質な分析が必要な場合
```

変更を検討すべきケース:
- **Opus を使用**: 対象リポジトリの依存関係が複雑、またはセキュリティ上重要なパッケージを扱っており、徹底的な分析に価値がある場合
- **Haiku を使用**: コスト最適化が優先で、対象リポジトリが主にリスクの低い patch 更新を受け取る場合
